# 首版交易市场与模拟数据粒度

**Status**: accepted（2026-10-22 · 本轮需求讨论）

首版从现货 BTC/USDT 完成一条完整策略链路：公开行情、4 小时信号、回测、模拟成交、虚拟资金、风险控制和绩效报告；同时接入 USDⓈ-M 永续的公开行情与历史资金费数据，为后续 Carry 策略准备，但首版不把永续自动执行作为完整交付。历史数据除现有日线、4 小时 K 线和资金费率外，增加 1 分钟 K 线采集与保存，以支持更细的历史路径模拟；1 分钟数据不能证明限价单排队顺序，也不能保证订单成交，因此模拟成交仍须采用保守假设并标明不确定性。

首版交付为完整的本地模拟交易闭环，而非静态展示：市场行情、策略版本管理、回测中心、模拟交易、模拟账户与组合、订单与交易记录、风控与告警、系统设置与日志，以及总览仪表盘，共九个页面。应用采用 React + Vite + ECharts 前端、独立 Python 后台与 SQLite；后台不依赖浏览器持续打开。首版仅调用币安公开行情接口，不使用私有交易 API 密钥，不查询真实账户、不发送真实委托，服务仅允许本机访问。

## Consequences

- 首版“支持两个市场”指数据接入覆盖现货与 USDⓈ-M 永续，不代表两个市场都有可自动运行的完整策略执行链路。
- 首个端到端策略使用现有 BTC/USDT 4 小时趋势策略作为工程测试对象；其现有负向样本外结果不得被忽略，也不得作为已获准的盈利策略。
- 1 分钟数据用于改善模拟成交路径检查，不取代交易所逐笔成交与订单簿数据；不可据此声称精确重现真实成交。
- 策略通过盈利验收的历史最大回撤上限暂定为 6%，且不替代单笔风险、当日熔断与组合风险限制。
- 建议风险限制：单笔计划风险不超过账户资金 0.5%，当日亏损 1.5% 时停止新增风险，组合计划风险不超过 2%；达到 6% 累计回撤暂停整套方案复审。以上为首版候选硬门槛，不代表未来最大亏损上限保证。
- 盈利验收须至少使用 5 个滚动样本外窗口、扣除全部交易成本后的正期望、95% 置信区间下界高于零、多重比较修正和专项风险检查；成本提高至基准假设的 1.5 倍时仍须达到预先冻结的稳健性要求。样本不足时判为“证据不足”，不得降门槛。
- 工程模拟验收同时要求至少连续运行 30 天与至少 30 笔完整往返模拟交易；若实际策略交易频率不足，不得为凑样本而改策略，应延长观察或标记“证据不足”。工程验收不等同于盈利验收。
- 所有策略参数、数据区间、费用与滑点假设、策略版本、回测和模拟运行批次都必须可追溯；修改策略创建新版本，模拟重置创建新批次，不覆盖历史数据。
- 行情未收盘、过期、缺失、时序异常或补录未完成时，禁止产生新模拟订单。保护模式解除前必须完成恢复前检查，并由用户明确确认恢复。
- Windows 重启或服务崩溃后，后台服务可自动启动，但策略默认暂停；不得因为状态恢复成功就自动恢复策略。
- 每个策略使用隔离模拟账户，初始总虚拟资金池默认为 1,000 USDT；组合视图可以汇总结果，但必须保留单策略收益与风险的独立归因。
- 研究呈现站点继续依照 ADR-0001 只读、构建期烘焙和离线可开；交易工作台另有运行时数据链，不得回写或改变既有研究成果口径。
